# Pilot Checklist

## Before Event

- Create the event in `/admin/events/new`.
- Confirm title, description, location, start time, and end time.
- Open the event detail page.
- Test the QR check-in URL on a phone.
- Confirm the certificate page loads after a test check-in.
- Decide who can access the admin event detail page during the pilot.

## During Event

- Display the QR code at the entrance or opening slide.
- Ask participants to choose the correct role.
- Keep the event detail page open to monitor participant count.
- Have a fallback check-in device ready.

## After Event

- Review participant names, roles, certificate status, and points.
- Spot-check several public certificate URLs.
- Record organizer notes about missing fields or workflow friction.
- Decide whether profile pages, CSV export, or certificate revocation should be prioritized next.

## Privacy Checklist

- Public certificate pages do not expose participant email.
- Public pages do not expose internal point ledger details.
- Test data is clearly marked as test data.
- Admin access is limited to trusted pilot organizers.

## Participant Feedback Questions

- Was the QR check-in easy to use?
- Did the public proof page feel useful?
- Was the role selection clear?
- What information should be shown or hidden on a public proof page?
- Would you share this proof page after the event?

## Organizer Feedback Questions

- Was event setup clear?
- Was the participant list useful during the event?
- Did the role-based point system match your community needs?
- What admin controls are missing?
- What privacy controls would you need before using this with a larger audience?

## Payment Willingness Questions

- Would you pay for event proof tracking?
- Which features would make the product worth paying for?
- What budget owner would approve this tool?
